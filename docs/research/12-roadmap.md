## v1 · 多 session 数据中心（切片 ①）

> 核心命题（05/00）：用户的首要痛点是"多 session 无法形成数据中心式的沟通"。契约层从第一天就按多进程设计（06 §7），
> v1 是**加法不是重写**——全部条目"只加不改"。

| 条目 | 内容 | 关联决策 |
|---|---|---|
| hub daemon | 常驻协调进程（`host/hub` 已留位）；多客户端同时连接 | K5、G24 归属 |
| 发现表（Registry） | 谁在线/在干什么/属于哪些 gate；事件驱动的内存活状态 | K10 |
| gate 水平可见性 | session 主 agent 间互见 + 显式 `join_gate` | K12（依赖 S13/S14，**口径已拍**） |
| 路径规范化 + repo_id | EvalSymlinks→小写→统一分隔符→去尾；`project_id`/`repo_id` 按 git root 聚合 | **S13/S14 已拍** |
| agentlink 完整 | Presence / Discover / Inquiry / Broadcast / Handoff 五件套（库形态） | K18 |
| 在线表注入 | 主 agent 上下文常驻在线表：**默认 50 行 / 每行 summary ≤100 token / gate 过滤；全参数可配 + 运行期动态管理**；恒在 prompt 末尾 | **K14/K15/Q5 已拍**、Q4 |
| 多 worktree 隔离 | 并行任务各占工作区 | 陷阱 4-7 已铺垫 |
| 完整 TUI | 终端日常交互面（Web 已有） | O6 |
| loop 事件化 | v0 控制流 → 事件驱动；契约不变纯增量 | F4 |
| 模型目录 | 内置快照 + 在线拉取 + 刷新 | I5 |
| env 补全 | 全分层 + **TOML 配置文件**（`%APPDATA%\alasol\config.toml`/XDG，env > 文件）+ global/agent/task 作用域 | **H15 已拍**、H14/H20 |
| hub 级监控 | CPU/内存监控告警 | K9（收口项） |
| token 成本统计 | usage 进成本统计（**不回填快照**——快照=事前估算为正式口径） | **J21 已拍** |

**★ 决策清单**：`07` ★ 汇总表过滤 `v1` 注记（K10/K12/K18/K20/H14/H20/Q4/Q6/R8 等）。**开工前置已清**：五条分岔已拍板（见文末）；其余按 §4.5.1 施工中自决。

> 核心命题：长时程自主跑久了，两件事开始咬人——**权限边界**（V8 写保护是声明式的）与**上下文**（必然超窗口）。

| 条目 | 内容 | 关联决策 |
|---|---|---|
| OS 沙箱 | seatbelt / bwrap / Win32 原生（01 有 V1/V2 落地路线）；`SandboxedExecutionEnv` 换上 | H9、V8、K8(v2 半) |
| 深度压缩 + 级联 | tiered 真做（含 **tiered% 锚定**——J21 拍板时明确留 v2）；级联走 **goal ledger C 案**（J19 基础已备） | J9/J10/J17/J18/J20/J21(锚定半) |
| 图投影点亮 | node/edge 表 + 内存图 → `change_impact` → escalate 客观依据 | G2c(已定)/G2f/G18-G21 |
| 跨 provider 上下文交接 | 换模型不丢上下文——行业真空，差异化卖点 | I4 |
| 写保护升级 | V8 边界由沙箱真正收口 | V8、陷阱 8 |
| 门禁增强 | 依赖缓存 / review-tip 失效 / 冲突预测 | V4/V6/V7 |
| 存储接口扩展 | 图/blob 接口随图投影与大输出落地 | G1/G2（收口项） |
