> 版本边界是**提案**（2026-10-28 整理），动工前按需在 `07` 收敛对应 ★ 条目。

## v1 · 多 session 数据中心（切片 ①）

> 核心命题（05/00）：用户的首要痛点是"多 session 无法形成数据中心式的沟通"。契约层从第一天就按多进程设计（06 §7），
> v1 是**加法不是重写**——全部条目"只加不改"。

| 条目 | 内容 | 源头 |
|---|---|---|
| hub daemon | 常驻协调进程（`host/hub` 已留位）；多客户端同时连接 | 06 §6/§7、K5 |
| 发现表（Registry） | 谁在线/在干什么/属于哪些 gate；事件驱动的内存活状态 | K10、G17b |
| gate 水平可见性 | session 主 agent 间互见（`gates(A) ∩ gates(B) ≠ ∅`）+ 显式 `join_gate` | K11/K12 |
| agentlink 完整 | Presence / Discover / Inquiry / Broadcast / Handoff 五件套（库形态） | K18、K22 |
| 在线表注入 | 主 agent 上下文常驻在线表（上限与筛选已定，K15） | K14/K15、Q4 |
| 多 worktree 隔离 | 并行任务各占工作区 | 11 v1 清单、陷阱 4-7 已铺垫 |
| 完整 TUI | 终端日常交互面（Web 已有，TUI 是并列面） | O5/O6 |
| loop 事件化 | v0 控制流 → 事件驱动；**契约不变，纯增量** | F4 |
| 模型目录 | 内置静态快照 + 在线拉取 + 周期刷新（v0 只有 `alasol models` 在线发现） | I5 |

**依赖的 ★ 决策点**（动工前收敛）：K12（自动/显式 gate）、K13（role）、K16/K20/K21（层级语义细化）、K24/K25/K26、K29（fork 语义）、G24（索引器归属 hub）。

## v2 · 深度执行与安全

> 核心命题：长时程自主跑得久了，两件事开始咬人——**权限边界**（写保护 V0 是声明式的）与**上下文**（必然超窗口）。

| 条目 | 内容 | 源头 |
|---|---|---|
| OS 沙箱 | seatbelt / bwrap / Win32 原生（受限令牌/容器，01 有 V1/V2 落地路线）；`SandboxedExecutionEnv` 换上 | H9、V8、K8、01 §落地 |
| 深度压缩 + 级联 | tiered 分级压缩真做（v0 只预留接口）；级联走 **goal ledger C 案**（目标/约束出上下文，切断级联链） | J9/J10/J12/J17/**J18-C**/J19、J20/J21 |
| 跨 provider 上下文交接 | 换模型不丢上下文——**行业真空**（kosong 静默丢弃、pi 不完整），差异化卖点 | I4 |
| 写保护升级 | V8 边界（bash 可绕）由沙箱真正收口 | V8、陷阱 8 |
| 图投影点亮 | 依赖图 → `change_impact` 可达性 → escalate 闸门客观依据（表结构 v0 已定，投影未点亮） | G2c/G18-G22、W16 |

**依赖的 ★ 决策点**：J17/J18（级联方案确认 C+A）、J20（缓存成本联动）、G18/G19/G20（图查询分层/内存预算/闭包缓存）、V 系列余项、S14（repo_id 聚合）。

## v4 · 规模化与评测

> 核心命题：证明它好用（评测），让它撑得住（检索/远程/跨机）。

| 条目 | 内容 | 源头 |

## 横切纪律（各版本通用，不随版本变）

- **契约演进（F7）**：对外发布后只增不删、不改义；弃用标 `x-deprecated`（发布前的破坏性变更须在 `contracts/INVENTORY.md` §5 记账）
- **退出评审循环**：每阶段/每版本 coding 完成 → critic 探查 → reviewer 修正 → 循环至 clean（11 §2 硬门禁）
- **唯一事实源**：一切状态由事件流 fold 得出；ledger/黑板事件化（F5/G23）
- **fail-close**：审批缺席、策略无命中、静默失败一律从严
- **Windows 一等**：陷阱清单（11 §3，现 21 条）每版本照抄
