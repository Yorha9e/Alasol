## v1 · 多 session 数据中心（切片 ①）

> 核心命题（05/00）：用户的首要痛点是"多 session 无法形成数据中心式的沟通"。契约层从第一天就按多进程设计（06 §7），
> v1 是**加法不是重写**——全部条目"只加不改"。

| 条目 | 内容 | 关联决策 |
|---|---|---|
| hub daemon | 常驻协调进程（`host/hub` 已留位）；多客户端同时连接 | K5、G24 归属 |
| 发现表（Registry） | 谁在线/在干什么/属于哪些 gate；事件驱动的内存活状态 | K10 |
| gate 水平可见性 | session 主 agent 间互见 + 显式 `join_gate` | K12（**依赖 S13/S14**，见讨论议程） |
| agentlink 完整 | Presence / Discover / Inquiry / Broadcast / Handoff 五件套（库形态） | K18 |
| 在线表注入 | 主 agent 上下文常驻在线表（上限与筛选） | K14/K15、Q3/Q4（参数见讨论议程） |
| 多 worktree 隔离 | 并行任务各占工作区 | 陷阱 4-7 已铺垫 |
| 完整 TUI | 终端日常交互面（Web 已有） | O6 |
| loop 事件化 | v0 控制流 → 事件驱动；契约不变纯增量 | F4（已 ✅ 标注形态，v1 做驱动化） |
| 模型目录 | 内置快照 + 在线拉取 + 刷新 | I5 |
| env 补全 | 全分层 + 配置文件源 + global/agent/task 作用域 | H14/H15/H20（H15 形态见讨论议程） |
| hub 级监控 | CPU/内存监控告警（goroutine 隔离对冲的最后一块） | K9（出入注记收口） |
| token 计量接入 | provider usage 回填（或明确"恒为估算"口径） | J21（出入注记收口，见讨论议程） |

**★ 决策清单**：`07` ★ 汇总表过滤 `v1` 注记（16 条）+ 上表收口项。其中**需要先拍板的分岔见文末议程**；其余按 §4.5.1 施工中自决。

## 动工前讨论议程

> 按 §4.5.1：**真分岔**才上桌；纯实现细节施工中自决。以下五条建议 v1 开工前拍板——

### v1 开工前建议拍板（影响架构的分岔）

1. **S13/S14 路径规范化与 repo_id**（牵动 K12）——gate 自动加入 `repo:<repo_id>` 依赖 repo_id；而 `hash(cwd)` 前的规范化正好踩 Windows 陷阱 4（符号链接/大小写/分隔符/尾斜杠）。**要拍**：规范化口径 + worktree 多 cwd 聚合到同一 repo 的判定（git root 查找）。
2. **K29 fork 复制语义**——07 原文就是"待细化"。**要拍**：fork 时 ledger 快照/gate 成员/agent 树/worktree 谁复制谁不复制（07 的倾向：只复制 ledger 快照与 gate 成员）。
3. **K15 在线表注入参数**——上限 N、summary 限长、过滤规则（gate）；暴露等级默认 `summary`（K14/Q5 已有倾向）。**要拍**：三个数（N=50？限长多少 token？）+ 末尾注入规则（Q4 已定"必须末尾"，无须再议）。
4. **H15 凭据配置文件形态**——用户级配置的格式与位置（TOML + XDG？Windows 侧放哪？），以及与进程 env 的优先级。**要拍**：格式/路径/优先级三件。
5. **J21 token 计量口径**——快照是**调用前**生成的，天然只有估算；usage 是**调用后**才有的。**要拍**：a) 明确"快照=事前估算"为永久口径（usage 只进成本统计）；或 b) usage 回填（事后修正事件/下一快照用真实值）。倾向 b 的轻量版。

### 施工中自决（§4.5.1，不必上桌）
